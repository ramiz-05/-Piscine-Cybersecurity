Security Lab 02

Race Condition

Use a single-use coupon twice by sending two requests at the same moment.

OWASP A06:2025 · Insecure Design CWE-362

01. What It Is

A race condition happens when two requests run at the same time and the result depends on which one finishes first. If a server checks a coupon but only marks it used later, both requests can pass the check. It is a check-then-use flaw: OWASP A06:2025 Insecure Design and CWE-362.

03. Why It Matters

Race conditions can cause duplicate coupon redemptions, double withdrawals, oversold stock and other money-related bugs, because every request thinks it is the only one.

Real incident: In 2015, researcher Egor Homakov showed that sending two Starbucks gift-card transfers at the same moment made the balance get credited twice, adding money to a card from nothing.

04. The Fix

Reserve the coupon before the first wait. A second request then sees it as used and is rejected.

Fixed implementation Fixed

Security improvement: The highlighted line closes the gap between checking and using the coupon, so the same concurrent payload now redeems it only once. Real servers must do this atomically, for example with a single database UPDATE ... WHERE used = false, a lock or a transaction.
