Security Lab 01

Insecure Direct Object Reference (IDOR)

Read another employee's payroll record by changing one number in a request.

OWASP A01:2025 · Broken Access Control CWE-639

01. What It Is

IDOR happens when an app uses an ID sent by the user (like slip_id=1002) to fetch a record without checking that the record belongs to them. Changing the ID in the request is enough to read someone else's data. It is OWASP A01:2025 Broken Access Control and CWE-639.

03. Why It Matters

Missing authorization checks let an attacker read, and sometimes change, other people's payroll, orders or documents just by editing an ID.

Real incident: In 2019, First American Financial's website served title-insurance documents by a sequential number in the URL. Changing one digit showed other people's files, exposing about 885 million records, including bank and Social Security numbers.

04. The Fix

Every resource request must verify that the authenticated user has permission to access the requested record. Base64 encoding or hiding IDs does not replace authorization.
